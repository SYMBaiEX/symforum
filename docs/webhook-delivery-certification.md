# Webhook delivery certification

This kit verifies that an allowlisted HTTPS endpoint can receive the published
[AsyncAPI event contract](/api/agent/asyncapi.json) without sending secrets to
SYMBaiEX support, chat, logs, or source control. It is local-only: the receiver
binds exclusively to `127.0.0.1`, accepts a bounded number of events, and exits
after a bounded timeout.

## Local receiver

Create or rotate a test subscription through the authenticated API. Store its
one-time signing secret in a secret manager. Do not use a production secret for
this certification.

Provide the secret once through a process environment variable:

```sh
SYMBAIEX_WEBHOOK_SIGNING_SECRET='<secret-from-your-secret-manager>' \
  bun scripts/webhook-cert-receiver.ts --port 8788 --max-events 2 --timeout-ms 60000
```

For a terminal where environment variables are unsuitable, pipe the secret from
a secret manager and use `--secret-stdin`. Do not paste it as a command-line
argument; command histories and process listings can expose arguments.

```sh
secret-manager read symbaiex-webhook-test | \
  bun scripts/webhook-cert-receiver.ts --secret-stdin --port 8788
```

The accepted route is exactly `POST /webhooks/symbaiex`. It preserves raw bytes
until the complete body arrives, then verifies the raw-body HMAC
(`HMAC-SHA256(timestamp + "." + body)`), the `v1=` signature form, five-minute
timestamp tolerance, exact header/body event id and type, and the complete
published AsyncAPI JSON Schema surface (references, `allOf`, required fields,
types, constants, enums, minimum/maximum values, URI format, and closed
objects). It also rejects duplicate event ids. Replays return `409`; invalid or
stale signatures return `401`; bodies over 16 KiB return `413`.

The receiver destroys unfinished request bodies and open sockets when its
configured deadline expires, then closes itself. This is a deliberately
bounded certification utility, not a durable webhook service.

The fixed fixture at `fixtures/webhooks/document-changed.json` is safe for local
tests only. It contains no subscription material and is deliberately unsigned;
the receiver validates live signatures generated by the sender.

## External HTTPS test endpoint

The receiver is intentionally not an internet-facing service. To certify live
delivery, an operator must separately provide an HTTPS test endpoint that is
under their control and then ask an authorized SYMBaiEX operator to add its
exact hostname to `EVIDENCE_WEBHOOK_ALLOWED_HOSTS`.

Use a dedicated test hostname, pin its TLS configuration, restrict inbound
traffic to the smallest practical network boundary, and forward the request to
the local receiver only through an authenticated, temporary tunnel or a managed
test environment. Keep the path `/webhooks/symbaiex`; do not place the signing
secret in the URL, hostname, tunnel configuration, browser, or logs.

Before external configuration, confirm:

1. The subscription owner can create or rotate a disposable test secret.
2. The endpoint hostname is exact, HTTPS-only, and approved for the allowlist.
3. Application logs redact request headers and never store raw signatures or
   secrets.
4. A valid fixture-derived delivery gets `204`, replay gets `409`, a tampered
   body gets `401`, and an over-limit body gets `413`.
5. The temporary allowlist entry, test subscription, secret, and tunnel are
   removed or revoked when the certification is complete.

No DNS, tunnel, environment, allowlist, subscription, or external webhook
configuration is performed by this kit.
