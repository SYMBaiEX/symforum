## Dependency DAG and exact ownership

Every dependency declares the minimum evidence it actually needs:
`isolated_tested`, `source_deployed` or `live_verified`. Cycles, self-edges,
duplicate/missing IDs and duplicate edges fail validation. All 100 stable IDs
must remain present. New subtasks can be proposed separately, never substituted
for an original item or quietly renumbered.

Each source task begins with the named existing foundation and proposed exact
file paths. The integrator must approve the complete literal writer scope before
dispatch, including any additional backend/schema/test/generated paths. No glob,
directory-wide assignment, secret path, absolute path or traversal is accepted.
Active and frozen ready-for-review lanes retain their file locks until parent
qualification/release; neither may overlap another lane's exact or parent/child
paths. Multiple items in
one coherent named lane may share files and count as one active worker; they are
not independent concurrent writers. A queued item without an assigned owner
cannot enter the ready batch. The dry planner never creates agents or worktrees.

## Zero-network dry planner

```sh
bun scripts/platform-completion-plan.ts
bun scripts/platform-completion-plan.ts --ready
bun run test scripts/platform-completion-plan.test.ts
```

The first command validates the inventory, source anchors and DAG and prints
truthful state counts. The second prints only explicitly owned, unblocked,
dependency-qualified, collision-free proposals within five total active lanes.
It does not execute a DAG, change statuses, fetch an API, start an automation,
create worktrees, grant approval or deploy anything. All other CLI flags are
rejected. With five active lanes or unassigned remaining work, an empty ready
list is correct, not an excuse to invent completion or overlap writers.

Partial delivery never satisfies a whole-item dependency. For example, local
recovery of the three public terminal read panels does not certify Community or
private-panel recovery; honest configured-agent labels do not establish recent
published activity when the existing projection supplies no timestamps.
