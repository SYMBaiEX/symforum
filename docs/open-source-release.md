# Open-source release gate

The repository remains private. A license and release-preparation changes are
not permission to change visibility or publish packages.

## Implemented controls

- Mailbox links are generated by the backend, expire, and are not returned to
  signup callers. Legacy token arguments are ignored for old-client compatibility.
  Old unversioned links require a fresh emailed link; subscription consent and
  topic preferences remain unchanged. Profile access requires a matching verified
  mailbox, including previously linked records.
- Public handle sign-in never resolves a private email into a redirect URL.
- A shared streaming body reader rejects and cancels oversized requests before
  buffering the full body; the webhook retains raw-byte HMAC verification.
- The owner AI console exposes only read tools. Explicit admin screens handle
  updates, email sends and scheduling. Budget accounting remains enabled.
- Root, Eliza worker and gateway dependencies are audited independently,
  including development dependencies. The Node-only worker maps the browser
  crypto dependency to Node's built-in crypto API instead of the unpatched
  browser cryptography dependency. Its bundled upstream browser-only fallback
  is not a supported runtime; do not repurpose this worker for a browser build.
- Third-party workflow actions and container bases are pinned; Dependabot and
  history/tree secret scanning is documented as a local release check. Tests are
  not blanket-excluded from secret scanning. GitHub Actions are intentionally
  skipped at the owner's request; they are not a release gate.
- MIT code licensing, asset notices, contribution guidance, private security
  reporting, conduct rules, PR guidance and code ownership are present.

## Required before the visibility change

- [ ] Confirm the exact release commit's tests, typechecks, lint, five application
  builds, worker checks, clean container install and dependency audits.
- [ ] Confirm tree/history secret scans on all exposed branches/tags, not only
  the default branch. Keep private operator files and detailed audit proofs out
  of release artifacts.
- [ ] Review and deploy the relevant application security changes; use synthetic
  and non-sending checks to verify the live boundaries. Preserve independent auth
  cutover flags, agent budgets, schedules and all uncertain-operation holds.
- [ ] Configure and verify branch rules and required maintainer reviews. The current
  private-repository plan returned 403 for protection/ruleset access. Do not
  claim protections are enabled without readback.
- [ ] Verify native secret scanning, push protection and private vulnerability
  reporting as supported by the selected repository plan/visibility.
- [ ] Have the owner separately authorize public release. Keep private until then.

Use [SECURITY.md](../SECURITY.md) for reports. Do not publish private audit details
or open exploit reports while a vulnerable deployment remains active.
